OpenSSL recursive seed-source initialization: stack exhaustion and clean failure

A concrete case of an initialization failure boundary. A recursive RAND seed-source construction could exhaust the call stack. A reviewed change introduced a clean failure path. This is a public example of the boundary-oriented repair work associated with Shin (GitHub: shin4141).

The failure and the verifiable repair trail

  1. OpenSSL issue #32683 — source problem and upstream discussion.
  2. OpenSSL maintainer-committed repair, aeeca5a — upstream adopted change.
  3. Original PR #32685 — submitted by shin4141; the PR is closed, not directly merged. Upstream adoption is through the separate maintainer commit above.

The evidence shows one documented repair contribution and its upstream adoption. It is not a claim of employment by OpenSSL, a security certification, a paid client engagement, or a guarantee that another system has the same defect.

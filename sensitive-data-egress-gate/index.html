最大被害量の設計 / Maximum Loss Design

もし管理者アカウントが1つ破られたら、何件の個人情報まで届きますか？

100件ですか。
10,000件ですか。
ALLそれとも全件ですか。

認証を守るだけでなく、破られた後の最大被害量を設計する。

Sensitive Data Egress Gateは、侵入・認証情報悪用・内部不正・誤操作の後でも、一度の事故で失える最大量に上限があるかを設計します。

全量到達の条件を整理する↗ 自社の段階を確認する↓
守る対象

個人情報 / 本人確認資料 / 医療情報 / 給与・銀行口座 / KYC・KYB / 顧客DB

02 / THE IDEA

ATMは、暗証番号だけで全額を引き出せない。

ATMでは、暗証番号を知っていても口座残高の全額を一度に引き出せない。機微なデータにも同じように、一度に失える最大量を設計できます。

これは単なるレート制限の話ではありません。

量・時間・判断する人・送信先を組み合わせて、データを外へ出す条件を定めます。

01一度の取得量一度に何件までか
02累積取得量繰り返すと何件までか
03時間枠どの期間で数えるか
04追加承認誰の判断を加えるか
05送信先どこへ出せるか
06権限変更後の待機新しい権限をいつ使えるか
07緊急時の特別経路例外時に、誰が何を許可するか

03 / FIVE-LEVEL SELF-CHECK

あなたのシステムは、どの段階ですか？

1つの認証情報が悪用されたとき、実際にどこまで取得できるかを考えてみてください。

現在の取得経路に最も近い説明を選んでください。

この条件を相談する↗

これは点数ではなく、条件の見取り図です。Level 5が、すべての会社の正解ではありません。業務要件に応じて適切な構造は異なります。選択だけで実装の有効性が確認されるものではありません。

分からない場合は、今どの条件なら全量を取得できるかを整理するところから始められます。

06 / HOW WE WORK

設計から、実装後の確認まで。

社内の状況と、開示できる範囲に合わせて進めます。

01 / DESIGN

オーダーメード設計書

コードや内部構成を外部へ出したくない企業向け。業務要件からRelease条件を設計し、実装は顧客側のエンジニアで進められます。

  • 取得上限・累積上限
  • 時間・承認人数と役割
  • 送信先・緊急経路
  • 監査証跡・復旧条件
  • 導入優先順位
02 / IMPLEMENTATION REVIEW

見せられる範囲をレビュー

見せられる範囲のコード・構成・テストを確認。量・時間・承認・経路の条件が、意図どおり実装されているかを整理します。

共有できる情報に合わせて、確認範囲を定めます。

03 / VERIFICATION

実装後の事故半径を確認

実装後に、設計どおり事故半径が制限されているかを確認。確認できた条件と、残る未確認事項を明確にします。

合意した範囲・環境で確認します。

  1. Design
  2. 社内で実装
  3. Verification

承認人数に一律の正解はありません。2-of-3 / 3-of-5などは設計例であり、実際の役割・条件・時間は各社の業務要件に合わせて定めます。

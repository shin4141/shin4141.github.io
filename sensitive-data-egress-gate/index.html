最大被害量の設計 / Maximum Loss Design

「侵入されない会社」を約束するのではなく、

侵入されても、全件流出しにくい会社へ。

管理者アカウントが1つ破られたとき、何件の個人情報まで届きますか？

100件ですか。
10,000件ですか。
ALLそれとも全件ですか。

多要素認証（MFA）・パスキー・生体認証などは、侵入の可能性を下げます。Sensitive Data Egress Gateは、その先──1つが破られた後の最大到達量を小さくする設計を扱います。

全量到達の条件を整理する↗ 自社の段階を確認する↓
守る対象

個人情報 / 本人確認資料 / 医療情報 / 給与・銀行口座 / 顧客・法人確認（KYC・KYB）/ 顧客情報

02 / 設計の考え方

ATMは、暗証番号だけで全額を引き出せない。

ATMでは、暗証番号を知っていても口座残高の全額を一度に引き出せない。機微なデータにも同じように、一度に失える最大量を設計できます。

これは単に取得の頻度を制限する話ではありません。

量・時間・判断する人・送信先を組み合わせて、データを外へ出す条件を定めます。

01一度の取得量一度に何件までか
02累積取得量繰り返すと何件までか
03時間枠どの期間で数えるか
04追加承認誰の判断を加えるか
05送信先どこへ出せるか
06権限変更後の待機新しい権限をいつ使えるか
07緊急時の特別経路例外時に、誰が何を許可するか

強い認証だけでは、最大被害量は決まりません

多要素認証（MFA）、生体認証、パスキーなどは、不正アクセスの可能性を下げます。しかし、認証後に1つの権限で全件取得できるなら、最大到達量は全量のままです。

入口を強くすることと、入られた後に被害が及ぶ範囲（事故半径）を小さくすることは別の設計です。

これは点数ではなく、条件の見取り図です。段階5が、すべての会社の正解ではありません。業務要件に応じて適切な構造は異なります。選択だけで実装の有効性が確認されるものではありません。

分からない場合は、今どの条件なら全量を取得できるかを整理するところから始められます。

段階5の代表設計例：Escalation Multisig Gate

影響が大きいほど、承認の段階を増やす設計です。全量・全量近接の取得では、単に承認人数を増やすだけでなく、影響量に応じて承認の仕組みそのものを段階的に強くします。

段階4：追加承認がある。

段階5：影響量に応じて承認の仕組みそのものを段階的に強くする。

最終責任者の認証情報だけでは取得を許可できません。最終承認は、前段の申請・通知・待機・必要な中間承認と条件固定が成立している時だけ有効です。

段階5の唯一の正解ではありません。承認する立場の数・必要承認人数・最終責任者の構成・待機時間は、各社の業務要件・責任分担・運用を継続できる条件に合わせて設計します。最終責任者は1名でも、3名のうち2名の承認（2-of-3 Owner Seats）などの構成でも設計できます。

会社ごとに決める設計条件
  • 申請する立場・中間承認する立場・最終責任者
  • 各段階の承認人数・最終責任者の人数・各条件での待機時間・通知対象
  • 取得量の境目・送信先・対象データの範囲・承認有効期限・緊急経路
取得許可の成立条件と承認の失効ルール
  • 申請者と独立承認者を分けるApplicant ≠ Approver申請者自身を独立承認者として数えません。
  • 最終責任者も承認の順序を省略できないOwner cannot bypass the chain最終責任者が直接「申請 → 承認 → 取得許可」を行い、前段の条件を省略することはできません。
  • 条件変更で承認失効対象データの範囲・取得量・送信先・申請者・取得許可の種類のいずれかが変わると、既存承認は失効します。
  • 承認有効期限承認は対象の申請・取得許可と期限に紐付けます。期限切れや、将来の別の取得許可への使い回しは認めません。
  • 緊急経路の分離通常経路へ流用せず、緊急経路固有の対象範囲・期限・承認する立場・操作記録を要求します。

05 / 何を設計するか

セキュリティ機能を増やす前に、「1つ破られたとき最大何件失えるか」を設計します。

多要素認証（MFA）、権限管理、取得頻度の制限（Rate Limit）、承認フロー、情報持ち出し対策（DLP）などを個別に見るだけでなく、「最大何件まで到達できるか」という1つの境界にまとめ、社内で実装できる目標とする状態へ変換します。

評価の中心は、最大到達量（Maximum Extraction）です。1つの認証情報が悪用された場合、確認できた経路の範囲で最大何件まで到達できるかを整理します。

経路をまたぐ分析（cross-path analysis）、脅威の想定（threat modeling）、被害が及ぶ範囲の分析（blast-radius analysis）は、既存の安全性確認でも行われます。本サービスは対象と評価軸を絞り、一つの成果物にまとめます。

一般的な幅広い安全性の確認（Security Review）

  • 複数のリスク・攻撃経路・制御を広く確認
  • 指摘事項・改善提案を返す場合がある

Sensitive Data Egress Gate

  • 機微データの取得・持ち出しに対象を限定
  • 最大到達量を評価の中心にする
  • 現在の状態 → 目標とする状態の境界値を設計
  • 実装後に確認する条件まで定義
取得量・時間・承認する立場・送信先・例外経路Volume / Time / Seat / Destination / Exception

広く見る代わりに、「最大何件失えるか」を深く設計する。

経営側と実装側が、同じ境界を見て判断できます。

経営側は「どこまでの損失を許容するか」を判断し、エンジニア側は「何を実装すればその境界になるか」を確認できます。同じ設計書で、双方の判断をつなぎます。

  1. 現在の状態Current State現在どこまで行けるか
  2. 目標とする状態Target Stateどこまで許すか
  3. 何を変えるかDesign Delta何を変えるか
  4. 実装後の確認Verification実装後に確認すること
